# AI Agent 深度认知学习计划（改自用版）

**日期**：2026-07-12 09:30  
**方法论基础**：肖璟《如何快速了解一个行业》的假设驱动 + MECE 拆解 + DIKW 自检

## 目标

建立对 AI Agent 的**第一性原理级理解**——从零设计一个 Agent 时，知道该怎么设计、哪些地方会卡住、什么能做、什么做不了。核心不是投资判断，而是脑中有一张清晰的结构图，能判断新论文/新产品的真正贡献在哪、局限在哪。

## 初始假设（阶段零）

| 假设 | 内容 |
|------|------|
| H1 | Agent 架构 = "LLM 当大脑 + 工具当手脚 + 记忆当经验"。反例：纯推理 Agent（无工具调用）是否还叫 Agent？ |
| H2 | LLM 单次上下文窗口限制是复杂任务的最大瓶颈之一 |
| H3 | 核心挑战不在模型智能，在执行链路可靠性 |
| H4 | 多 Agent 协作的核心挑战是**一致性和通信开销**，而非简单叠加 |

每学完一个模块修订假设，结束时对比"我认为的"与"实际情况"——差距即认知增量。

## 阶段零：建立最小领域认知（~3-5 天）

### 必读三篇论文

| 论文 | 核心问题 |
|------|----------|
| [[lilian-weng]]: LLM Powered Autonomous Agents（综述） | Agent 由哪几块组成？ |
| [[ReAct]]: Synergizing Reasoning and Acting（2022） | 推理和行动怎么协同？ |
| Reflexion: Language Agents with RL（2023） | Agent 怎么从失败中学习？ |

读法（假设驱动式）：先读 abstract + intro → 写"这篇声称解决什么问题" → 看图和方法第一段 → 跳过数学看实验 → 合上论文用两句话讲给别人听。

## 阶段一：逐层深入——MECE 拆解 + 假设验证（~4 周）

### AI Agent 的 MECE 知识结构

```
                        AI Agent
                           │
        ┌──────────────────┼──────────────────┐
        │                  │                  │
    [感知层]           [认知层]           [行动层]
    怎么理解输入       怎么思考决策          怎么执行
        │                  │                  │
    ├─ 文本理解       ├─ 任务分解        ├─ 工具调用
    ├─ 多模态输入     ├─ 推理(LLM core)  ├─ 代码执行
    ├─ 上下文理解     ├─ 自我反思        ├─ API 编排
    └─ 意图/目标解析  ├─ 规划             └─ 多 Agent 协作
                     └─ 决策/选型
                          │
                    [记忆层] ←→ [评估层]
                    怎么存储         怎么判断对错
                          │                  │
                     ├─ 短期记忆       ├─ 自动评估(规则)
                     ├─ 长期记忆(RAG)  ├─ 自动评估(模型)
                     └─ 经验学习       └─ 人类介入
```

### 第 1 周：认知层——LLM 怎么"思考"？

**假设**：Agent 的认知质量 ≈ LLM 推理能力 + Prompt 组织方式

| 子假设 | 验证方式 | 预期产出 |
|--------|----------|----------|
| CoT 本质是"让模型在生成答案前先把推理过程显式化" | 读 CoT 原论文 + 对比实验 | 理解 CoT 适用/不适用场景 |
| ReAct 每一步的 "Thought" 可被错误推理带跑 | 跑 ReAct demo，观察 Thought 什么时候开始胡说 | 理解 Agent 失败的主要模式 |
| 任务分解粒度是关键——太粗没用，太细太贵 | 读 Plan-and-Execute 论文，对比"先计划后执行"vs"边想边做" | 理解何时该 plan 何时该 react |

**周末产出**：200 字——"LLM 作为 Agent 大脑的三个核心能力和三个核心限制"。

### 第 2 周：行动层——Agent 怎么"动手"？

**假设**：行动的瓶颈不在"能不能调用工具"，在"调哪个工具、传什么参数、怎么处理返回结果"

| 子假设 | 验证方式 | 预期产出 |
|--------|----------|----------|
| Function Calling 可靠性取决于工具描述质量 | 同一工具写两种描述，对比 Agent 选对概率 | 理解 prompt engineering 对 Agent 的影响 |
| 多步工具调用最常见失败是"上下文漂移"——中间结果淹没原始目标 | 跑 5+ 步工具调用链，看任务完成率 | 理解复杂任务易跑偏的原因 |
| 代码执行比 API 调用更灵活但不更安全 | 读 CodeAct / SQL+Python Agent 论文 | 理解行动选项的 trade-off |

**周末产出**：500 字——"Agent 执行层的五个难点和当前解法"。

### 第 3 周：记忆层——Agent 怎么"积累经验"？

**假设**：记忆层是 Agent 目前最不成熟的层——短期靠窗口（有限），长期靠 RAG（粗糙）

| 子假设 | 验证方式 | 预期产出 |
|--------|----------|----------|
| 短期记忆核心矛盾是"窗口放不下"vs"塞太多稀释注意力" | 读 Longformer / Block Recurrent Transformer 思路摘要 | 理解窗口限制的物理约束 |
| RAG 解决事实检索，解决不了经验积累和策略迭代 | 对比 RAG Agent vs 微调 Agent 论文 | 理解 RAG 不能解决什么 |
| Reflexion 让 Agent 用自身失败经验形成内部反思——比 RAG 更高级的记忆形式 | 读 Reflexion 论文 + 跑 demo | 理解"从失败中学习"的 Agent 设计 |

**周末产出**：一幅"Agent 记忆层全景图"——短期/中期/长期各用什么方案及各自局限。

### 第 4 周：多 Agent + 评估层——"团队"怎么协作？

**假设**：多 Agent 不是"多加几个 LLM 就行"，核心挑战是**避免冗余 + 保证一致性 + 通信效率**

| 子假设 | 验证方式 | 预期产出 |
|--------|----------|----------|
| Multi-Agent 核心价值不是"更聪明"，是"更可靠"（互相 check） | 读 AutoGen / MetaGPT 论文 | 理解单 Agent vs 多 Agent trade-off |
| Agent 评估是学术界比工业界更头疼的问题 | 读 AgentBench / SWE-Bench 评估论文 | 理解"怎么判断 Agent 做得好不好"有多难 |
| Human-in-the-loop 在可见未来不可或缺 | 读 AutoGen 中 human feedback 章节 | 理解为什么 Agent 目前不可能完全自主 |

**周末产出**：一页纸总结"AI Agent 真实现状"——能做多好，做不了什么。

## 阶段二：动手贯穿始终

### 每周必做

| 周 | Demo 任务 |
|----|-----------|
| W1 | ReAct 最简单 demo（调一个工具） |
| W2 | 加记忆（向量数据库 + 对话历史） |
| W3 | 加错误处理（工具调用失败怎么办？） |
| W4 | 多 Agent 合作完成任务 |

### 失败日志（最有价值的学习材料）

```
* 时间：___
* 任务：___
* Agent 做了什么（出乎意料的事）：___
* 失败在哪一步：___
* 为什么失败——是因为：
    □ 模型幻觉？
    □ 工具描述写得不清楚？
    □ 窗口太长丢了目标？（上下文漂移）
    □ 规划粒度不对？
    □ 评估层没拦住错误？
* 如果让我改，我会怎么改：___
```

一条失败日志 = 对 Agent 内部机制的一次真正理解。与 [[失败日志]] 机制同源。

## 阶段三：DIKW 自检

每周用 [[DIKW模型-研究方法论]] 自检：

- 停留在"读过了" → 数据/信息层（还没学完）
- 能讲给别人听为什么 → 知识层（基本功）
- 能判断新论文真正的贡献在哪 → 智慧层（真正的认知）

每周目标往前推一层：
- W1-W2：从"读了很多资料" → 能讲清楚"Agent 是什么"
- W3-W4：从"能讲清楚" → 能判断"这篇论文真正贡献了什么"
- W5-W6：从"能判断论文" → 能预判"这个领域下一步往哪走"

## 验收标准：学习结束时能回答这 5 个问题

| 问题 | 检验点 |
|------|--------|
| Q1：如果从零设计一个 Agent，架构图是什么？每层用哪些技术？为什么？ | 阶段一没做完则答不出 |
| Q2：给定新论文，能辨别它贡献在哪一层（认知层突破还是工程层优化）？ | 未达知识层则答不清 |
| Q3：Agent 任务失败，能定位是哪一层的 bug（推理错？工具调用错？记忆丢？评估没拦住）？ | 失败日志不够则定位不了 |
| Q4：初始假设对了几个？为什么对/错？ | 此对比 = 真正学到的东西 |
| Q5：能给出一个可证伪的预判吗——Agent 未来能做到什么、做不了什么？ | 能 = 深度认知建立 |

## 时间安排

| 阶段 | 时间 |
|------|------|
| 阶段零（最小认知） | ~3-5 天，论文 + 结构图 |
| 阶段一（逐层深入） | ~4 周，每周深一层，周末产出 |
| 阶段二（动手验证） | 贯穿全程，每周 demo + 失败日志 |
| 阶段三（DIKW 自检） | 每周一次，周末 15min |

每天投入 1-1.5 小时，6 周后建立的不是谈资，而是结构级认知。
