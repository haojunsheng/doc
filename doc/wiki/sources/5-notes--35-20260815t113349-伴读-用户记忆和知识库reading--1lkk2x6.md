# 伴读：《AI Agent 工程》第三章 用户记忆和知识库

## 全局地图

这一章要让 Agent 从"只记得当前对话"升级到"跨会话记住用户、记住知识"：一边构建用户记忆（评估、存储、表示），一边构建知识库检索管道（分块、嵌入、混合检索、结构化索引），最后两条线索在**双层记忆架构**处汇合——Advanced JSON Cards 提供"概览"，上下文感知检索提供"细节"。

## 核心主张

**记忆的目标不是记录，而是形成一个关于用户的预测模型。** 人类朋友的记忆是模糊印象（"他大概率不吃香菜"），Agent 体系追求精确可检索（`dietary restriction: vegetarian`）。两种精度需求之间的张力是本章暗线。

**评估记忆能力需三层次递进，而非并列指标：** 基础回忆 → 多会话检索 → 主动服务。第二层与第三层边界不在"是否需要人参与"，而在"谁发起动作"。

**记忆表示格式存在不可兼得的张力：** 四种格式在可更新性、语义完整性和关联保持上各自有代价，无绝对最优，实践中采用混合模式。

**Mem0 v2→v3 的演进揭示了"错误代价决定存储策略"的原则：** 错排可重试（低风险），错删不可逆（高风险），故 append-only + 检索时排序更优。

**混合检索的本质是"双编码器/跨编码器两级漏斗"：** 通用成本-质量决策结构，不限于 RAG。

**用户记忆与知识库的根本差异在于"推断" vs "组织"：** 底层同而上层异。

## 关键术语

| 英文/术语 | 中文 | 本文含义 |
|-----------|------|----------|
| Trajectory | 轨迹 | 单次会话完整原始记录，append-only |
| LoCoMo | 长期对话记忆基准 | 约300轮/35会话的超长多轮对话评测 |
| Simple/Enhanced Notes | 简单/增强笔记 | 最小事实 / 完整上下文段落 |
| JSON Cards | JSON 卡片 | 三层嵌套结构的记忆表示 |
| Advanced JSON Cards | 高级 JSON 卡片 | 加 backstory/person/relationship 的记忆 |
| User as Code | 可执行记忆 | 用带类型 Python 对象表示用户状态 |
| Episodic/Semantic/Procedural | 情景/语义/程序记忆 | 事件/知识/流程 |
| Mem0 / Memobase | — | 记忆管理框架 |
| append-only | 只增不改 | 事件只追加不删除的日志模式 |
| Chunking | 文档分块 | 把长文档切成适合独立检索的片段 |
| Embedding | 嵌入 | 把文本映射成向量，语义近则向量近 |
| 分布假设 | distributional hypothesis | 词的语义由共现环境决定 |
| 倒排索引 | inverted index | 词→文档的反向映射表 |
| TF-IDF | 词频-逆文档频率 | 文档内重要 × 跨文档区分度 |
| BM25 | — | 词频饱和+长度归一化的检索打分 |
| RRF | 倒数排名融合 | 抛得分看排名，Σ1/(k+rank) |
| Bi-Encoder / Cross-Encoder | 双编码器/跨编码器 | 独立编码 vs 拼接交互 |
| RAPTOR | 树状层次索引 | 自底向上聚类摘要成树 |
| GraphRAG | 图检索增强 | 实体关系图，多跳推理+消歧 |
| Agentic RAG | 智能体化 RAG | 检索=工具，ReAct 多轮迭代 |
| Contextual Retrieval | 上下文感知检索 | 给块补前缀再索引（Anthropic） |
| 双层记忆架构 | — | JSON Cards 概览常驻 + 上下文检索按需取细节 |
| Proposer-Reviewer | 提议者-审核者 | 知识更新的双 Agent 审核闭环 |
| 压舱石 | — | 模型之外的可靠锚点（证据/代码/原始记录） |
