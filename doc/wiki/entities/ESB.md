# ESB（Enterprise Service Bus）

集中式中间件平台，用于集成异构应用和服务，代表 SOA 时代管理服务间通信的尝试。

## 失败的下沉案例

ESB 在 [[深度研究-凤凰架构构建可靠的大型分布式系统deep-learn]] 中被引用为 **H2 的典型失败案例**：

> "ESB 试图统一业务编排 —— 没人愿意交出这个。"

与替代服务发现（ESB 曾取代但后来越界）不同，ESB 试图集中化**业务逻辑编排**——路由、转换、协议适配和跨企业系统的流程协调。

## 失败原因

| 因素 | 说明 |
|------|------|
| **业务逻辑所有权** | 没有团队愿意把集成逻辑交给中央总线 |
| **单点故障** | 总线故障 = 整个企业故障 |
| **厂商锁定** | 专有协议和工具使迁移困难 |
| **配置复杂性** | 视觉化集成流在大规模下无法维护 |
| **性能瓶颈** | 所有流量汇聚到单一架构 |

## 与服务网格对比

| 维度 | ESB | 服务网格（Istio） |
|------|-----|------------------|
| 统一层级 | 业务编排 | 通信治理 |
| 逻辑位置 | 总线中集中 | 代理中分布 |
| 失败原因 | 业务逻辑神圣不可让渡 | 通信是繁琐但不神圣 |
| 采用结果 | 被组织拒绝 | 尽管复杂仍渐进接受 |

## 现代视角

ESB 模式在现代 API 网关和集成平台中依然存在，但单一集中式集成总线梦想已基本放弃。教训：**你可以下沉管道，但不能下沉目的。**
