# 演进式架构

架构不是被发明出来的，而是持续演进的结果。每种架构解决上一代问题同时带来新缺陷，没有终点，只有因果链。

## 演进路径

原始分布式时代 → 单体时代 → SOA → 微服务 → 后微服务 → 无服务

## 「换房子」vs「造房子」

架构腐化只能延缓无法根治。正确做法是**「换房子」而非「造房子」**：后一套房子不是前一套的升级版，只有逻辑继承关系；每换一次都让团队适应了当前阶段的复杂度。不再憋大招等完美最终架构，用「换房子」的方式一步步演进，每一版都让用户拿到价值。

## 与飞轮的结构性同构

[[飞轮：模型内化vs Harness卸载]] 与演进式架构高度同构：模型能力内化 ↔ 基础设施能力成熟，Harness 层逐层卸载 ↔ 分布式复杂度逐层下沉。两者都描述了一个「能力从主体转移到底层支撑」的演进过程。
