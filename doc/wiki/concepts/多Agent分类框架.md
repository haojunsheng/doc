# 多 Agent 分类框架

## 定义

多 Agent 协作的二维分类框架，用于判断"什么场景适合多 Agent"。

## 二维矩阵

| | 上下文共享 | 上下文独立 |
|--|-----------|-----------|
| 对等 | 同层 Agent 共享同一上下文，协作完成任务 | 各 Agent 独立工作，结果汇总 |
| 管理者 | 管理者 Agent 分配任务，工作 Agent 共享上下文 | 管理者 Agent 分配任务，各工作 Agent 独立执行 |
| 去中心化 | 无中心协调，Agent 间直接通信 | 无中心协调，Agent 通过共享环境通信 |

## 关键结论（H3 检验）

> "上下文独立 + 管理者"是当前最实用的形态。

理由：
1. 上下文独立降低了通信开销和一致性问题
2. 管理者提供了任务分解和结果整合能力
3. 适用于电话+电脑这种模态隔离场景

## H3 裁决

- **单强 Agent + 良好工具设计**在多数通用任务上更优
- **多 Agent 价值集中在**：模态隔离（电话+电脑）、责任隔离（不同权限域）、并行专长（翻译+润色）

## 去中心化模式（2026 新增）

同机对等 Agent 实例是 2026 年新增的协作形态，与管理者模式的关键差异是信任假设：
- 管理者模式：信任管理者 Agent 的公正性
- 去中心化模式：无信任假设，通过协议保证正确性

## 验证方式

用电话+电脑 Agent 案例解释为什么它恰好落在"上下文独立 + 管理者"这一格；再找出一个"对等协作"更优的反例。
