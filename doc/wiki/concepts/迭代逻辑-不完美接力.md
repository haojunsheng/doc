# 迭代逻辑——不完美接力

> 面对复杂系统，不再追求终极方案。只问：当前最大的问题是什么？我给出的解法会制造什么新问题？后人有能力接手吗？

## 核心定义

**迭代逻辑**是指系统（尤其是王朝、组织）通过多代接力、逐代解决最急迫问题的方式获得弹性的机制。每一代人都只解决眼前最紧急的问题，不管方案是否完美，留给下一代人再解——正是这种「不追求一劳永逸」的务实精神，让系统避免了刚性崩盘。

与[[胜利推迟隐患机制]]的区别：后者是被动地在单次竞争中推迟问题爆发（如项羽赢的同时消耗不可再生资源），迭代逻辑则是**主动把推迟制度化**，每一代人都自觉地接受不完美方案，把副作用交给后人。

## 汉朝四百年迭代链条

```
刘邦：半郡县半封建 → 同姓王坐大
        ↓
文景：削藩 → 中央集权 → 军国扩张
        ↓
武帝：扩张 → 国库空虚 → 外戚填权
        ↓
宣元：外戚专权 → 王莽篡汉
        ↓
光武：豪族联盟 → 豪族坐大 → 党锢 → 崩塌
```

每一代人都用当时最好的方案解决了当时最大的问题，但每一个方案都在几十年后成为下一代人的死局。系统弹性不在于方案本身是否完美，而在于**后人有没有能力继续迭代**。

## 判断决策好坏的新标准

> 判断一个决策好坏的标准，不是它会不会制造新问题，而是后人有没有能力解决它制造的新问题。

- 刘邦传下的同姓王问题 → 文景有能力削掉 ✓
- 武帝传下的外戚问题 → 宣帝还能控住，元帝之后彻底失控 ✗
- 失控不是因为问题更大了，是因为后继者不再有能力迭代

这个标准可以迁移到组织管理、政策制定、技术架构等任何需要多代延续的复杂系统。
