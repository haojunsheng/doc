# 链表边界四类陷阱

## 核心论点

链表题的错误 90% 出在边界，不在主逻辑。这四类边界是高频 bug 来源：

| 边界类型 | 典型场景 | 常见错误 |
|----------|----------|----------|
| **空表** | 头节点为 null | 未判空直接访问 head.next |
| **单节点** | 只有一个节点 | 循环条件 `while(node.next != null)` 跳过最后一个节点 |
| **头尾节点** | 插入/删除首尾 | 忘记更新 head 指针或 tail.next |
| **环检测** | 判环/找环入口 | 快慢指针步长设置错误，或未处理无环情况 |

## 验证方式

手写以下题目，统计 bug 分布：
- LRU 缓存（结合散列表 + 双向链表）
- 链表反转
- 求中间节点（快慢指针）
- 环检测（Floyd 判环算法）

## 与散列表的组合

LRU 缓存是链表 + 散列表的经典组合：散列表提供 O(1) 查找，双向链表提供 O(1) 移动。两者结合是面试高频题。

## 失败日志建议

本周必须记录 ≥1 条边界 bug，这是链表学习最有价值的素材。
