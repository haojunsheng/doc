# 需求排序矩阵

## 定义

通过**频次（高频/低频）**与**弹性（弹性小/弹性大）**两个维度，对已确认存在的需求进行排序，判断该需求"好不好赚钱"的二维判据工具。

## 适用场景

在可行性分析中，已确认某需求真实存在（销售可行性通过），但需进一步筛选：哪些需求值得投入资源去满足。适用于导入期行业的商业模式评估。

## 矩阵结构

```
              弹性小（刚性需求）        弹性大（可替代）
            ┌─────────────────┬─────────────────┐
  频次高    │  ✅ 最佳          │  🟡 还行         │
            │  例：吃饭、理发   │  例：猪肉        │
            │  毛利 40-60%     │  可换牛羊肉      │
            ├─────────────────┼─────────────────┤
  频次低    │  🟡 凑合         │  ❌ 最差         │
            │  例：婚庆        │  例：景点骑马    │
            │  一辈子一次      │  可选可不选      │
            └─────────────────┴─────────────────┘
```

## 简单判据

**频次高 + 弹性小**，至少占一样，才可能有好收入。

## 经典案例

**中欧商学院龚焱教授的东南亚太阳能案例**：当地缺电，但居民已适应黑暗，对照明需求极低；真正刚需是制冰（用于保鲜）。不做实地调研，永远发现不了这个隐藏需求。

## 与框架其他部分的关系

- 属于[[五维分析框架-肖璟]]中的"可行性→销售可行性"环节
- 在[[产业生命周期-行业分析第一性原理]]的导入期分析中作为第二步使用（第一步是判断需求真伪：时间对标/空间对标）
- 与[[假设驱动研究]]相配合：先提出"这是个好需求"的假设，再用频次×弹性矩阵验证

## 局限性

- 仅适用于消费品/服务类需求排序，不适用于B2B工业品或投资品
- 频次和弹性的判断依赖经验，存在主观性偏差
