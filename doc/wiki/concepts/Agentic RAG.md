# Agentic RAG

## 定义

Agent 自主决定何时检索、检索什么内容的 RAG 范式，区别于固定流水线 RAG（预定义检索流程）。

## 与固定流水线 RAG 的对比

| 维度 | 固定流水线 RAG | Agentic RAG |
|------|--------------|------------|
| 检索触发 | 每个查询自动触发 | Agent 自主判断是否需要检索 |
| 检索内容 | 预定义查询模板 | Agent 根据上下文动态构造查询 |
| 延迟 | 可预测 | 不可预测（可能多次检索） |
| 适用场景 | 问答类、知识检索类 | 多步任务、需要判断的场景 |
| 失败模式 | 检索不到相关内容 | 检索过度/检索不足/检索方向错误 |

## 关键子假设（W2 子假设 2.3）

> Agentic RAG 优于固定流水线 RAG，但代价是延迟与不可控。

**验证方式**：写出一个固定流水线会失败而 Agentic 会成功的查询例子。例如：用户说"帮我处理上个月的账单问题"——固定流水线不知道"上个月"是哪个月，也不知道"账单问题"具体指什么；Agentic Agent 可以先检索当前日期和账单历史，再决定下一步。

## 与上下文漂移的关系

Agentic RAG 增加了检索的灵活性，但也增加了上下文漂移的风险——Agent 可能在检索过程中偏离原始目标，被中间结果误导。
