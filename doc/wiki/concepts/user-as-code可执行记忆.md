# User as Code（可执行记忆）

把用户状态表示为带类型的 Python 对象，让"存"和"用"发生在同一个可被解释器运行的介质里，而非分两步（先捞文本，再交给 LLM 去读去算）。

## 两阶段设计

1. **记忆阶段**：事实逐条追加到只增不删的日志（append-only）
2. **结构化阶段**：周期性从日志重新生成带类型 Python 对象（预写日志 + 周期性检查点）

## 三件从"LLM 心算"变"确定性代码"的事

1. **聚合统计**：不再靠 LLM 估算，代码直接求和/平均
2. **冲突发现**：类型约束显式检测不一致
3. **约束执行**：规则以代码形式硬编码，不可绕过

## 代价与张力

- **可读性代价**：代码记忆的读者是解释器，文本记忆的读者可以是用户自己（与 [[OpenViking]] 的 Markdown 可读路线对立）
- **结构预知代价**：类型化要求提前知道结构，而记忆是演化的，无法类型化的只能堆进 `notes: list[str]` 兜底
