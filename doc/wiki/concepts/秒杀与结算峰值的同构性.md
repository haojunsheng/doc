# 秒杀与结算峰值的同构性

秒杀的"削峰+排队+限流"三板斧与结算的"资金峰值防护"同构，差在"秒杀可以拒绝，打款不能丢"。

## 同构点

| 维度 | 秒杀场景 | 结算峰值场景 |
|:---|:---|:---|
| 流量特征 | 瞬时洪峰 | 大促打款洪峰 |
| 核心目标 | 保护下游不被打死 | 保护资金不被多付/漏付 |
| 基本手段 | 削峰 + 排队 + 限流 | 削峰 + 排队 + 限流 |
| 失败处理 | 用户看到"排队中" | 打款必须成功或明确失败 |

## 关键差异

**秒杀可以拒绝，打款不能丢。**

这意味着：
- 秒杀可以用"排队 + 异步处理 + 最终一致"
- 结算必须用"排队 + 同步确认 + 强一致"，或者"排队 + 异步处理 + 补偿机制"

## 设计启示

结算系统的峰值防护不能简单照搬秒杀方案。需要在"不丢钱"的前提下，通过队列缓冲、分批打款、事后对账等手段实现类似效果。
