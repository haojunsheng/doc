# 失败日志

## 定义

在动手实践阶段，系统记录每次错误发生的时间、任务、失败方式、根本原因和由此得出的洞察。是用"失败"作为数据来源的学习方法。

## 格式

```markdown
* 时间：2026-07-20
* 任务：让 Agent 搜索最新 AI 新闻并总结
* 失败方式：调用了错误的工具 API（给了旧版的 Wikipedia endpoint）
* 失败原因：工具描述写得不够精确
* 这揭示了什么：Agent 对工具描述的质量高度敏感 → 
  → 子假设补充：Agent 工程的 80% 工作量在工具描述和 prompt tuning
```

## 核心价值

- 把隐性知识显性化：每次踩坑都是对某一层真实难度的测量
- 验证假设：H2（瓶颈在工程可靠性）可以通过失败日志中的错误类型分布来检验
- 复用性：失败的格式可以抽象为通用模板，适用于其他技术学习项目

## 关键洞察（预期）

Agent 工程的瓶颈往往不在模型能力，而在工具描述的精度和 prompt tuning 的工作量。这是用失败日志这种"从做中学"方式才能发现的洞察，而非读论文能直接得到的结论。
