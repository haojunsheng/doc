# Agent 五层架构

## 定义

将 AI Agent 系统按功能拆分为五个层次的分析框架，用于 MECE 拆解和理解各层的成熟度差异。

## 五层结构

```
                    AI Agent
                         │
    ┌────────────────────┼────────────────────┐
    │                    │                    │
[感知层]            [推理/规划层]          [行动层]
怎么理解世界          怎么做决策             怎么执行
    │                    │                    │
  文本理解            Prompt Chaining       API 调用
  多模态理解           Chain of Thought      代码执行
  环境感知             ReAct                 浏览器操作
  意图识别             Tree of Thought       数据库 CRUD
                    Plan-and-Execute
                    Multi-Agent 编排
                         │
               [记忆层] ←→ [评估层]
```

| 层级 | 核心问题 | 关键技术/方法 |
|------|---------|-------------|
| 感知层 | 怎么理解世界 | 文本理解、多模态理解、意图识别 |
| 推理/规划层 | 怎么做决策 | CoT、ReAct、Tree of Thought、Plan-and-Execute、Multi-Agent 编排 |
| 行动层 | 怎么执行 | API 调用、代码执行、浏览器操作、数据库 CRUD |
| 记忆层 | 短期/长期存储 | RAG、MemGPT、LangMem、向量数据库 |
| 评估层 | 怎么判断对错 | 规则校验、LLM-as-judge、人工审核 |

## 成熟度排序（预期）

```
行动层（最成熟）> 感知层 > 推理/规划层 > 记忆层 > 评估层（最不成熟）
```

## 与 Agent = LLM + 上下文 + 工具 公式的关系

五层架构是「Agent = LLM + 上下文 + 工具」公式的展开版本：
- **感知层 + 记忆层** ≈ 上下文（眼睛）
- **推理/规划层** ≈ LLM（大脑）
- **行动层** ≈ 工具（手脚）
- **评估层** ≈ Harness（可靠性机制），跨层保障

## 上下文工程四机制的精细拆解（W1 补充）

[[上下文工程四机制]] 将"上下文"这一大块进一步拆解为四个独立机制：
- 提示工程 → 影响感知层和推理层
- Skills 按需加载 → 影响行动层的工具描述
- 状态栏 → 影响记忆层的呈现方式
- 压缩 → 影响记忆层的容量管理

## 与相关概念的关系

- [[ReAct]]：推理/规划层的核心方法，"边想边做"的范式
- [[Harness（可靠性机制）]]：跨层的约束、验证与纠正机制
- [[上下文漂移]]：上下文管理失败的典型模式，发生在感知层→推理层→行动层的传递链上
- [[工具描述敏感性]]：行动层与推理/规划层之间的接口问题
