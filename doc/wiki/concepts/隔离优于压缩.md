# 隔离优于压缩

## 定义

上下文工程中的一种设计哲学：与其让一个 Agent 记住一切（然后通过压缩机制丢失信息），不如把任务分给多个子 Agent，各自只记各自的事。

## 核心逻辑

上下文窗口的本质约束决定了：信息越多，单条信息被压缩或删除的概率越高。一个试图记住所有对话历史的单 Agent，最终会陷入「什么都不知道」的困境——因为上下文太长，什么都要压缩。

隔离策略的本质是**用空间换质量**：
- 每个子 Agent 只维护自己需要的上下文
- 子 Agent 之间通过明确的接口传递信息（而非让单个 Agent 自己回忆）
- 信息在传递时被显式处理，不会因为压缩而默默丢失

## 与现有概念的关系

- [[上下文工程四机制]] 中的「压缩」机制处理的是单 Agent 的上下文超限问题，而「隔离」是另一种思路：不压缩，而是分工
- [[KV Cache 工程约束]] 指出消息前缀不能乱动，隔离策略天然规避了这个问题——每个子 Agent 有自己的前缀
- [[Harness（可靠性机制）]] 中提到的「多子 Agent 各自只记各自的事」正是隔离优于压缩的实践形式

## 实践含义

- 当单 Agent 上下文压力大时，优先考虑拆分而非压缩
- 子 Agent 之间的通信接口要显式、明确，避免隐式记忆依赖
- 这同样适用于多步骤任务的分解：每步一个 Agent，每步只携带必要信息

## 验证方式

- 对比同一任务：单 Agent + 压缩 vs 多子 Agent + 隔离，观察最终输出质量差异
- 观察多步任务中，单 Agent 的「忘记」点出现在哪里（通常是在压缩决策处）
