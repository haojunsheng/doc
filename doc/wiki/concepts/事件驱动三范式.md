# 事件驱动三范式

## 定义

事件驱动架构的三种处理范式，解决"训练同步 vs 部署异步"的根本矛盾。

## 三范式

| 范式 | 描述 | 适用场景 | 关键机制 |
|------|------|---------|---------|
| 取消式 | 收到新事件时取消正在进行的旧任务 | 用户主动中断场景 | 取消信号、状态回滚 |
| 队列式 | 事件放入队列，按序处理 | 高并发、保证顺序的场景 | 消息队列、优先级 |
| 并行式 | 多个事件并行处理，各自独立 | 独立任务、无共享状态的场景 | 隔离、资源分配 |

## 为什么需要事件驱动？

传统 Agent 是"请求-响应"模式：用户发送请求 → Agent 处理 → 返回结果。但真实世界是异步的：
- 用户可能随时打断
- 后台任务可能随时完成
- 外部事件可能随时发生

事件驱动是把 Agent 从"请求-响应"推向"异步长任务"的关键。

## 占位符是必要妥协

在事件驱动场景中，Agent 需要在中断后恢复，但恢复时的状态可能已经变化。占位符机制允许 Agent 标记"我正在处理 X"，后续事件到来时检查占位符并决定是继续、取消还是重定向。
