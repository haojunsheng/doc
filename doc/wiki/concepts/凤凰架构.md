# 凤凰架构

**不追求部件不坏，追求整体对个体失败的免疫。**

## 核心隐喻

每个部件都是一只不死鸟，会老迈、会涅槃重生；可靠不是让哪只鸟永远不死，而是让整个族群在单只鸟死亡时仍有后代接替、整体维持稳定。

## 三大支柱

1. **演进视角**：架构不是被发明出来的，而是持续演进的结果。每种架构解决上一代问题，也带来新缺陷。可靠性有了时间维度——不是在某个时点一次建成的，而是在一次次替代中被维持。

2. **下沉**：分布式问题不可避免，但解决它的位置可以迁移。注册发现、网关路由、负载均衡、容错、事务、安全等复杂度从代码层沉到基础设施层，让代码重归业务关注。

3. **治理**：微服务不是银弹。上微服务前先过目的、前提、边界三关；架构腐化只能延缓无法根治，唯一有效办法是「换房子」而非「造房子」的演进式设计。

## 与 Harness 的跨域同构

[[Harness（可靠性机制）]] 是 AI Agent 领域的等价概念：不追求模型本身不犯错，而追求整体对模型错误的免疫。凤凰架构是通用分布式系统的先驱版本，两者共享「接受故障、设计恢复」的核心哲学。
