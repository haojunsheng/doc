# 工具描述敏感性

## 定义

Agent 对工具描述的质量高度敏感——工具描述稍有不精确，Agent 就会调用错误的 API 或执行错误的参数。这是 Agent 工程中最为关键也最容易被忽视的环节。

## 核心洞察

Agent 工程的 **80% 工作量在工具描述和 prompt tuning**，而非模型选择或架构设计。

## 典型失败模式

| 失败方式 | 根因 |
|---------|------|
| 调用旧版 API endpoint | 工具描述中未明确版本号 |
| 参数传错类型 | 描述中未标注参数约束（如枚举值范围） |
| 工具名混淆 | 多个相似工具的描述未做区分 |
| 权限不足报错 | 描述中未说明前置依赖 |

## 实践含义

- 工具描述应当像 API 文档一样精确，而非自然语言草述
- 每次 Agent 失败时，检查工具描述是否是根因——这是失败日志中最常见的条目类型
- 对初学者而言，这是从"demo 能跑"到"产品可用"之间最大的鸿沟
