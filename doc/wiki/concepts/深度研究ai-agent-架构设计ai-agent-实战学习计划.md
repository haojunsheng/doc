# 深度研究——AI Agent 架构设计（《AI Agent 实战》学习计划）

**作者**：李博杰（Pine AI 首席科学家）
**领域类型**：H 型（T 为主、M 为辅）
**目标深度**：B. 能对话——能和 Agent 从业者有质量地讨论，能指出一个方案在上下文/工具/评估设计上的问题
**时间跨度**：约 10 周（每周 10–15 小时）

## 核心公式

> **Agent = LLM + 上下文 + 工具**

三元素分别对应三个层次：

| 层次 | 公式 | 直觉类比 | 学术对应 |
|------|------|---------|---------|
| 实现层 | LLM + 上下文 + 工具 | — | Policy + 观察空间 + 动作空间 |
| 直觉层 | 大脑 + 眼睛 + 手脚 | — | — |
| 学术层 | — | 决策器 + 感知器 + 执行器 | Policy + 观察空间 + 动作空间 |

## 初始假设（H1–H3）

### H1：上下文工程是瓶颈

> Agent 的能力瓶颈不在模型智能，而在上下文工程——固定同一个模型，只改上下文设计（消息结构、压缩、状态栏、Skills 加载），就能拉开 Agent 表现的档次差距。

**验证方式**：W1 跑第二章实验，改提示词看效果差异。消融实验显示去掉上下文组件、工具结果或系统提示词任何一块，系统显著退化（52.8% → 66.5%）。

**W7 复审**：Agentic RL 正在把工具调用能力训进模型参数，可能压缩上下文工程的生存空间。

### H2：新名词多为既有实践重命名

> 业界流行的 Agent 新名词（Skill、harness、loop engineering）绝大多数是既有工程实践的重新命名；近一年真正"新"的东西是评估与后训练方法。

**【2026-08-09 伴读修订·已确认】** 加一条限定：重命名并非没有价值——名词是大多数人低成本继承实践的通道；但读名词时必须带着它背后的实践问题去读，否则拿到的只是词。

### H3：单强 Agent + 良好工具设计多数情况下优于多 Agent 编排

> 在当前模型能力下，多数真实任务里"单个强 Agent + 良好工具设计"优于"多 Agent 编排"；多 Agent 的价值集中在少数天然分工的场景（如电话 + 电脑这种模态隔离任务）。

**验证方式**：W9 结尾做裁决。

## 核心论点与发现

1. **上下文窗口是"只有一半的检索引擎"，缺提炼层**——KV Cache 原理 + 状态栏/压缩/Skills 三大机制各自填补不同缺口
2. **SFT 记忆、RL 泛化**——后训练两条主线各司其职
3. **评估三维度**（环境 × 数据集 × 评判方法）——工具调用型与人机交互型是两种根本不同的评估范式
4. **LLM-as-a-Judge 可靠性取决于 rubric 设计**而非裁判模型本身
5. **四种更新载体**按更新成本 × 风险排序：知识文档 > Prompt 与 Skills > 程序与 Harness > 模型参数
6. **代码是元能力**——代码生成让 Agent 能内生生成新工具，是通用 Agent 的技术基座
7. **快慢思考分离**让交互能力与智能上限分别演进

## 方法论特征

- **假设驱动**：三假设贯穿全计划，W7 复审 H1，W9 裁决 H3
- **MECE 拆解**：每章拆 2–3 条子假设，每条配具体验证方式
- **动手验证**：每周 ≥1 个实验，难度分级 ★/★★/★★★
- **DIKW 自检**：每周填入自检表，确认停留在数据/信息/知识/智慧哪一层
- **失败日志**：每周 ≥1 条，模板固定五类原因（理解错机制/操作不到位/前提不具备/没拦住错误）
