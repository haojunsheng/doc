# 外部观测第三轴

## 定义

模型无论想得多深、试得多多次，都只在上下文已有的信息里打转，变不出上下文里没有的内容。要让 Agent 获取真实世界信息，必须引入第三条轴——用外部仪器观测，并将结果写回上下文。

## 为什么需要第三轴

前两条轴（模型内部推理、上下文中的历史信息）都受限于模型自身能力范围。"想得更久、试得更多"只是在已有上下文空间里搜索，不能产生新信息。只有外部观测才能突破这个限制。

典型例子：
- 模型不知道今天确切日期 → 外部时钟观测
- 模型不知道按钮是否真正被点击 → 截图/日志观测
- 模型不知道电话打了几次 → 通话记录观测

## 实践含义：状态栏的重新理解

状态栏的本质是把"闭卷考试"变成"随时查一眼真实世界"。状态栏中的信息**必须来自真实观测**，而不是让 LLM 自己统计或推断——否则"仪器"读出的就是错的刻度，引入系统性偏差。

这引出了 [[工具描述敏感性]] 的深层原则：模型感知到的世界与工具操作的世界不能有系统性偏差。

## 多 Agent 判断准则

第十章的核心观点：判断多 Agent 是否优于单 Agent，唯一标准是**是否引入了生成时不存在的新信息**。如果多 Agent 只是让多个模型在相同上下文里各自推理，并不能突破这个第三轴的限制，价值有限。

## 与上下文学习=检索而非推理的关系

[[上下文学习=检索而非推理]] 说明上下文窗口是"只有一半的检索引擎"——外部观测第三轴是这个"一半"的另一半：把真实世界的观测数据注入进来，让检索引擎有完整的数据源可以检索。

## 实践检查项

给每条注入上下文的信息问一句："这条信息是模型自己想不出的吗？"
- 想不出的（真实时间、执行结果、系统状态）→ 值得外部观测
- 能想出来的 → 只是替它省力，不是核心价值，不应占用上下文带宽
