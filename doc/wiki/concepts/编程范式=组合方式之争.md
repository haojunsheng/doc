# 编程范式 = 组合方式之争

OOP/FP/泛型的差异只在组合基元——对象/函数/类型。所有范式都在回答同一个问题：代码如何组合成系统？

## 核心命题 H4

编程范式之争（OOP vs FP vs 泛型）的本质是"组合方式之争"。这不是修辞，而是有实证支撑的判断：

| 范式 | 组合基元 | 错误世界观 | 典型语言 |
|:---|:---|:---|:---|
| OOP | 对象 | 错误是异常，应被抛出而非返回 | Java, C++ |
| FP | 函数 | 错误是一等公民，应被显式处理 | Go, Haskell |
| 泛型 | 类型 | 类型约束替代运行时检查 | Go (1.18+), Rust |

## Go 的组合优先哲学

Go 的设计是"组合优先"哲学的极端化：
- 委托优于继承
- 接口隐式满足（duck typing）
- 组合优于类型层级
- 显式错误处理（`if err != nil`）

## 错误处理是范式的试金石

返回码、异常、函数式 Either 背后是不同的"错误是否是一等公民"世界观。Go 选择显式返回错误而不是异常，与"错误的可见性"直接相关——错误应该被看见、被处理，而不是被忽略。
