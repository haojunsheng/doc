# 动态 Agent 公式

## 静态公式

> **Agent = LLM + 上下文 + 工具**

三层表述：

| 层次 | 公式 | 直觉类比 | 学术对应 |
|------|------|---------|---------|
| 实现层 | LLM + 上下文 + 工具 | — | Policy + 观察空间 + 动作空间 |
| 直觉层 | 大脑 + 眼睛 + 手脚 | — | — |
| 学术层 | — | 决策器 + 感知器 + 执行器 | Policy + 观察空间 + 动作空间 |

详见 [[Agent-LLM-上下文-工具]]。

## 动态公式（伴读原创贡献）

$$Agent(t+1) = Agent(t) + 评估回路(Agent(t))$$

**评估回路不是第四项，是作用于前三项的时间算子。**

构造过程：读者发现静态公式有真实缺口——评估、记忆、多 Agent 不在其中，将它们视为三项的推论过于勉强。选择"有缺口"选项，推出动态公式。

## 压力测试与边界定义

最强反驳来自作者的 RL 背景——reward 在环境侧不在 Agent 侧，三项公式边界划得干净。

**拆解**：边界划在"运行时进程"还是"持续交付的系统"？

- 若 Agent 定义为**运行时进程**：三项公式边界干净，评估是外部观察者
- 若 Agent 定义为**持续交付的系统**：评估回路必须是一等组件

## 结算系统类比

> **"系统的定义由'什么会出事'决定，不由'什么在实时跑'决定。"**

结算系统：对账不在交易实时链路里（常是夜间批处理），但没人敢说对账不是结算系统的一等组件。Agent 的评估回路同理——不在每次推理的实时链路里，但决定系统能否持续交付可靠结果。

## 四种更新载体（时间算子的实现）

[[四种更新载体]] 是评估回路的四种具体实现形式，按更新成本 × 风险排序：

| 载体 | 更新成本 | 风险 | 适用场景 |
|------|---------|------|---------|
| 知识文档 | 低 | 低 | 静态知识沉淀 |
| Prompt 与 Skills | 中 | 中 | 行为模式调整 |
| 程序与 Harness | 中 | 中 | 结构性约束 |
| 模型参数 | 高 | 高 | 深层能力提升 |

## 与 Harness 页的交互关系

[[Harness（可靠性机制）]] 是动态公式中的"保障层"——评估回路通过 Harness 来实现对 LLM/上下文/工具的约束与修复。二者构成一体两面：Harness 是静态保障，评估回路是动态进化机制。

## 与飞轮的关系

参见 [[飞轮：模型内化vs Harness卸载]]——评估回路产生的补救经验沉淀为训练信号，模型内化后对应 Harness 层可删，这是动态公式在长时间尺度上的表现。
