# KV Cache 工程约束

## 定义

KV Cache（键值缓存）是 LLM 推理过程中的核心优化机制，决定了上下文消息列表的工程约束边界。

## 三条核心结论

1. **前缀改动会导致整段 KV Cache 失效**：在消息列表前面插入或删除内容，会迫使模型重新计算所有后续 token 的 KV 值，成本剧增。这意味着上下文前缀一旦确定就不能随意修改。

2. **消息列表的顺序就是上下文的结构**：顺序改变 = 语义改变。模型对消息的理解严重依赖其在序列中的位置（首位、中间、末位）。

3. **状态栏应放在固定位置（末尾之前）**：将状态信息放在消息列表的固定位置（通常在工具调用结果之后、最新用户消息之前），而非历史中间，是为了最小化 KV Cache 失效影响——状态更新只影响后缀，不影响前缀缓存。

## 工程含义

- **不推荐**：在对话历史中间插入新消息或修改已有消息
- **推荐**：使用追加写入（append-only）方式构建消息列表
- **推荐**：状态栏/压缩结果放在消息列表末尾附近，而非开头

## 验证方式

跑 `chapter2/` 实验，打印真实请求的消息数组，观察不同消息顺序下的响应差异和成本变化。
