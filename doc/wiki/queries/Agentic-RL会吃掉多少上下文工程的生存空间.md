# Agentic RL 会吃掉多少上下文工程的生存空间？

## 问题背景

H1 假设：Agent 的能力瓶颈不在模型智能，而在上下文工程。

W7 出现的反向趋势：Agentic RL 正在把工具调用能力直接训进模型参数，这可能压缩上下文工程的生存空间。

## 关键问题

- 模型能力内化 vs 上下文工程，两者的分界线在哪里？
- 哪些能力更容易被训进参数？哪些必须留在上下文？
- 随着模型变强，上下文工程的"必要最小量"是增加还是减少？

## 相关假设状态

- [[H1H2H3假设体系]] 中的 H1 在 W7 面临正面复审
- 作者立场：模型变强会压缩上下文工程的生存空间，但永远吃不完（理由：训练以月计业务等不起 / 真实约束无法全部内化 / 每代模型都打开新前沿）

## 验证方向

- 跟踪 Agentic RL 的最新进展（如 GRPO、online RL 在 Agent 场景的应用）
- 对比同任务下"纯模型能力" vs "模型+上下文工程"的表现差异
- 关注 GPT-4o/o1/o3 系列中哪些能力是通过 RL 获得的，哪些仍然依赖上下文设计
