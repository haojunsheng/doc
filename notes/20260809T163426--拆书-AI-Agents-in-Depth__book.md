- **x**：为什么大多数 AI Agent 在 demo 里惊艳、上线就翻车？生产级 Agent 的核心挑战到底是什么？
- **f**：模型只是 Agent 的「大脑」，真正让 Agent 在生产环境里稳定工作的，是「Harness 工程」——上下文管理、工具编排、评估体系、安全护栏、错误恢复。Harness 和模型不是上下游关系，而是一条共同进化的飞轮：Harness 补上模型此刻做不好的事，这些补救反过来变成模型下一次迭代的训练信号。
- **f(x)**：不再只盯着模型排行榜选方案。把精力花在 Harness 层——评估、记忆、工具、安全——这些东西今天还是工程优势，明天就会被模型内化。真正的护城河在技术之外：独占数据、用户信任、渠道网络。

# x：作者在讨论什么问题

2025-2026 年，AI Agent 成了整个行业最热闹的话题。各种产品 demo 让人眼花缭乱——能写代码的、能做研究的、能操作浏览器的。但真到了生产环境，一个简单任务的成功率常常只有 50%-70%，多步任务更是断崖式下降。为什么？

李博杰一开篇就给出了一个简洁的公式：**现代 Agent = LLM + 上下文 + 工具**。三样东西缺一不可，但行业大多数讨论只围绕 LLM 的能力（哪个模型更强、哪个 benchmark 更高），忽视了上下文和工具这两个「Harness 层」的工程复杂度。模型可以在实验室里跑出高分，但能不能在真实用户的对话里保持几十轮不跑偏、能不能正确调用几十个工具、能不能在出错后自己恢复——这些问题不是模型升级能解决的，需要一套完整的工程体系。

这本书要回答的，正是这套工程体系应该怎么设计。

# f：作者怎样回答

全书十章，核心回答可以浓缩为三个关键词和一条飞轮。

**三个关键词：上下文、工具、评估。**

**上下文是 Agent 的「眼睛」。** 书里从 KV Cache 原理讲到分层压缩策略，讲透了一个看似简单实则致命的问题：Agent 的「记忆」不是无限的。每次和用户对话、每次工具调用，都在消耗有限的上下文窗口。一旦超出窗口，模型就会「忘记」之前发生的事。作者的解决方案是一套生产级的分层压缩机制：不同重要性的信息用不同方式存储——最新消息保持原样、近期对话做摘要、长期知识沉淀为文件。第二章结尾还有一个核心理念：「隔离优于压缩」——与其让一个 Agent 记住一切，不如把任务分给多个子 Agent，各自只记各自的事。

**工具是 Agent 的「手脚」。** 模型再聪明，不能操作文件、不能发邮件、不能查数据库，就只能在对话框里空转。但工具设计远比看上去复杂：粒度太粗则模型无法灵活组合，粒度太细则模型选不过来；工具描述写得太啰嗦占用上下文，写得太简单模型调用出错。书里有一个关键观点：代码是 Agent 的「元能力」——当模型能写代码时，它就不需要为每个场景预先定义工具，它可以自己造工具。这是为什么 Coding Agent 是所有 Agent 形态里最强的一种。

**评估是 Agent 的「方向盘」。** 没有评估，你就不知道改了一段提示词是让 Agent 变好了还是变坏了。书里的评估体系不是简单的「跑几个 benchmark」，而是一套从 Pass@k（能力上限）到 Pass^k（业务可靠性）到过程指标到失败归因的完整方法论。特别值得记住的一个区分：**模型厂商告诉你 Pass@k（试 k 次有一次成功就算成功），你的用户需要的是 Pass^k（连续 k 次都成功才算成功）。这是两个完全不同的指标。**

**一条飞轮：模型和 Harness 共同进化。** 全书结尾给出了最具洞察力的总结。Harness 层那些看起来丑陋的兜底代码——多级压缩、无数次重试、默认拒绝的权限判断——记录的其实是模型此刻还做不稳的地方。当下一代模型把这些约束内化，对应的 Harness 代码就可以删掉。而模型之所以能内化，又是因为 Agent 已经在真实业务里替它把这些坑趟了一遍。这就是一条自我强化的飞轮：模型越强 → Harness 越薄 → 模型从 Harness 的补救中学习 → 模型更强。但 Harness 永远不会消失，因为每一代模型都会打开新的能力前沿，前沿处恰恰是模型最做不稳的地方。

# f(x)：怎样回应这个世界

把 Harness 工程的视角放进 AI 行业，会改变三个常见的判断。

**不再迷信「换个模型就解决问题」。** 书里举了一个具体实验：不换模型、只优化 Harness，任务准确率从 52.8% 跳到 66.5%。在模型能力趋同的今天，Harness 层的差异才是产品体验的真正分水岭。如果你在造应用，你的技术杠杆在 Harness，不在选模型。

**但要清醒：Harness 优势是暂时的。** 模型每内化一层 Harness 的约束，就会顺手抹平一批只靠 Harness 建立的优势。所以「把 Harness 用来争取时间，把这段时间用来构筑技术之外的壁垒——独占的数据、稳固的渠道、用户的信任、网络效应」。

**评估体系是 Agent 产品的「操作系统」，没有它你永远在盲飞。** 书里反复强调一个观点：Agent 的故障是拜占庭式的——它不会直接 crash，而是给出看似合理但错误的答案。没有一套自动化的评估和归因系统，你根本不知道自己的 Agent 到底有多差、差在哪里。
