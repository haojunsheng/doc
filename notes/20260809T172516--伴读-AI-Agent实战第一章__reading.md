# 逐段伴读记录

## 流读：工具五分类、LLM、模型实验

- 事件触发工具分类勉强——是上下文入口而非动作空间，W3 第四章回看
- Kimi K3 实验关键澄清（Issue #30 推动）：RL 内化的是"何时调用、怎么用"的决策策略，不是工具本身
- 消融实验 1-1 是本章唯一硬证据

## [骨] 苦涩的教训与"方向认同，节奏务实"

### 结构标注

全章论证张力最大的一段。作者主动引入对全书最危险的反驳（人的先验终将输给规模），然后给出防守。论证骨架：让步方向（模型会吃 Harness）→ 防守节奏（但比直觉慢很多）。

### 碰撞记录

- **读者反驳**：用结算经验拆——MQ 再可靠应用层幂等也不能省，因为"什么叫同一笔"只有业务知道
- **注疏（背光·源流）**：Saltzer/Reed/Clark 1984 端到端论证——某些功能只能在端点正确实现，下层做只能是性能优化
- **读者贡献的框架**：Harness 两层——通用补丁层（会被吃掉，JSON 格式约束等）vs 业务语义层（结构上不可能被吃，"什么算对"只有业务能定义）

## [骨] 学习机制三路径

### 结构标注

全书的时间维度总图。三路径是动态公式 `Agent(t+1) = Agent(t) + 评估回路(Agent(t))` 的工程对应物。第八章四种更新载体把"外部产物"再拆三份（知识文档 / Prompt+Skills / 程序+Harness）。

### 碰撞记录

- **读者给出的分流判据**：看变化的频率
- **伴读者补全为三轴**：变化频率（定载体的"热"度）+ 可显式表达性（定能不能进参数）+ 可审计性（定必须留在哪）——业务语义层只能活在外部产物路径上，因为参数不可审计
- 同构点：规则引擎（Aviator）的分流逻辑 = Prompt/Harness/参数的分流逻辑

## [骨] ReAct 循环与轨迹

### 结构标注

第一章机制核心。LLM 本身无状态——纯函数 `f(轨迹) → 下一步`，ReAct 循环+轨迹才是状态机。轨迹 append-only，每次调用重放全量历史，代价是二次方增长。第二章上下文工程一整章就是打这个靶子。

### 碰撞记录

- **读者同构**：append-only 日志 → 状态重建 → 随长度退化 = 区块链的设计（中本聪初始设计也是全量回放，后来通过快照/UTXO 修剪/轻节点解决）
- **关键差异**：区块链需要多节点共识，Agent 只有一个大脑在读日志 → 压缩可以比区块链激进（LLM 自动摘要、小模型做压缩），代价是压缩丢关键信息（只能出错后发现，恰是第六章评估要解决的问题）

## [骨] Harness 工程六层

### ① 扩展公式：Agent = Model + Harness
Demo 视角 vs 生产视角。约束/验证/纠正不是独立模块，是上下文和工具身上的工程实践。

### ② 范式演进：提示 ⊂ 上下文 ⊂ Harness ⊂ Loop（层层包含）
硬数据：LangChain Terminal Bench 52.8%→66.5%（没换模型只换 Harness）；OpenAI 工程团队 10 倍效率也不靠模型。

### ③ 三原则 + ACI 防呆
简单（能 API 不框架）、透明（决策轨迹全可见 = 建立信任）、ACI 防呆（从 Agent 视角设计接口，SIM 卡缺角/微波炉门没关好不加热 → Poka-yoke）。

### ④ 编排模式：工作流 vs 自主 vs 混合
资金链路 → 工作流（节点顺序不可变、攻击面收敛在节点内）；用户意图理解/异常处理 → 自主模式；n8n 混合两者。

### ⑤ 护栏三层 + 人工干预
输入侧（越狱/注入/审核）、执行侧（工具风险评级低/中/高）、输出侧（PII 过滤/合规）。越狱 vs 提示注入区别：前者用户自己绕限制，后者通过外部数据间接操纵。人工干预两种触发：超失败阈值 + 高风险操作。

### ⑥ 章节-Harness 映射表（九行速查表）

### 读后一句话

> "对于做结算的我来讲，Harness值得我花大力气来学。因为涉及到资金，基本不可逆。没有好的Harness，很难去搞AI Agent。"

**L3（生出新问题）**——从"Harness 很重要"飞跃到"对资金领域它是入场券而非加分项"。而且指出书里一个隐含的张力：Harness 章只有 8 页，上下文工程章写了 1104 行——但资金场景的投资重应该在 Harness。
