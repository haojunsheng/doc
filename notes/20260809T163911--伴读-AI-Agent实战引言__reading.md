# 全局地图

## 一句话摘要

作者用 Pine 的实战经历论证：Agent 架构的好原则不是被发明的，是被真实业务倒逼出来的，所以它们先于名词存在、也穿越模型迭代周期。

# 逐段伴读记录

## 骨架段 1：实践在前，命名在后

### 结构标注

全文论证枢纽。Pine 三例（动态加载提示词≈Skill、防护机制≈harness、提议者-审核者≈loop engineering）是证据；"等名词流行就慢一步"是行动推论。修辞注意：排比三遍来自同一家公司，样本量为 1，制造的是"模式重复"感而非独立证据。

### 碰撞记录

- **读者反驳**（高质量）：对大多数人，业务没那么复杂，追名词/看论文就是理性策略；只有超大或创新公司有条件从实践中总结名词。
- **关键发现**：作者已提前让步——"业务要求不高、模型稍一升级就够用，就没有动力打磨架构原则"。主张 1 拆为弱版（名词是滞后指标，无人反对）与强版（追名词是系统性错误，需要前提）。
- **作者的补丁**：评估机制 = 把小业务压缩出大业务失败密度的装置（一天暴露 1000 个失败 vs 1 个）。
- **同构注疏（侧光）**：结算系统（对账/幂等/兜底，把不可靠组件包成可靠系统）与 Agent harness 同形——读者的本行经验就是 Agent 架构直觉。
- **收束（读者认可）**：H2 加限定——重命名并非无价值，名词是没有难业务者低成本继承实践的通道；但读名词必须带着背后的实践问题去读，否则只拿到词。
- **已写回学习计划**：H2 修订（2026-08-09）。

## 骨架段 2：核心公式 Agent = LLM + 上下文 + 工具

### 结构标注

全书几何原点。十章 = 三个分量的展开（上下文→2/3 章，工具→4/5 章，LLM→7 章）+ 让它变好（6/8 章）+ 边界扩展（9/10 章）。

### 碰撞记录

- **构造题**：评估、记忆、多 Agent 为什么不在公式里？候选 1（它们是三项的推论）vs 候选 2（公式有真实缺口，缺学习回路）。
- **读者选择**：2——评估回路是一等组件。
- **压力测试**：最强反驳来自作者自己的 RL 映射——reward 在环境侧不在 Agent 侧，三项公式是边界划得干净。
- **拆解**：边界划在"运行时进程"还是"持续交付的系统"？结算类比——对账不在交易实时链路里（常是夜间批处理），但没人敢说对账不是结算系统的一等组件。**系统的定义由"什么会出事"决定，不由"什么在实时跑"决定。**
- **精确版收束**：静态公式 `Agent = LLM + 上下文 + 工具`；动态公式 `Agent(t+1) = Agent(t) + 评估回路(Agent(t))`。评估回路不是第四项，是作用于前三项的时间算子；第八章四种更新载体（知识文档/Prompt/程序/参数）就是这个算子的实现。

## 流读段：主张 2 + Sutton

- "好原则穿越模型周期"是断言非论证，标记为"待验证"，押后到第十章兑现。
- "自举"（bootstrap）一词在 W4 第五章正面展开，也是 H1 复审（模型变强 vs 上下文工程）的关键变量。

## 读后一句话

读者原话："作者在引言中，其实想向大家表达的是，我们其实一直在实践了，但是大家都没意识到。带有鼓励大家的意思。"

**评级：L2（有判断）**——识别出了地图未标注的维度：修辞立场。

**伴读者推进**：鼓励是硬币一面；完整结构是"先赋权、再收门槛"——"你们早就在做了"（消除距离感）+ "但缺评估就不算真的在做"（重新定义标准）。这是课程讲稿的转化结构：让读者觉得"我上我也行"，同时觉得"我还差一套方法"。鼓励是真的，但它是有价格的鼓励，价格就是"没有评估就没有进步"。
