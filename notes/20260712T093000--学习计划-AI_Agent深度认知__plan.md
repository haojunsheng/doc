# AI Agent 深度认知学习计划（改自用版）

> 目标：建立对 AI Agent 的**第一性原理级理解**——
> "如果让我从零设计一个 AI Agent，我知道该怎么设计、哪些地方会卡住、什么能做、什么做不了。"
>
> 不是为了投资判断。是为了**脑子里有一张清晰的结构图**，
> 能判断一个新论文/新产品的真正贡献在哪、局限在哪。
>
> 方法论基础：肖璟《如何快速了解一个行业》的假设驱动 + MECE 拆解 + DIKW。

---

## 学习前：写下你的初始假设（越粗糙越好）

```markdown
*我的初始假设（2026-07-12）：*

H1: AI Agent 的架构是"LLM 当大脑 + 工具当手脚 + 记忆当经验"。
    验证：读 ReAct 和 Lilian Weng 综述——这三层是不是真的能覆盖？
    什么情况下不成立？→ 有没有"没有工具"也能叫 Agent 的？→ 有：纯推理 Agent

H2: LLM 的单次上下文窗口限制，是 Agent 做复杂任务的最大瓶颈之一。
    验证：跑一个需要 10+ 步的规划任务——看它在第几步开始"失忆"？

H3: 当前 Agent 的核心挑战不在"模型够不够聪明"，在"执行链路的可靠性"。
    验证：看最近半年 Agent 相关论文——是在改进模型能力，还是在改进执行成功率？
    什么情况下不成立？→ 如果大部分论文都在做模型改进 → H3 错

H4: 多 Agent 协作不只是一个框架问题，是一个"一致性和通信开销"问题。
    验证：读 AutoGen / CrewAI 论文——它们最被吐槽的局限是什么？
```

> 每学完一个模块回来改一个假设。**学习结束时对比"我认为的"vs"实际情况"——差距才是认知增量。**

## 阶段零：建立最小领域认知（~3-5 天）

> 肖璟：对所研究话题缺乏基本了解 → 先找专家或高质量综述，建立框架性认知。

### 0.1 精读 3 篇论文

读论文不是为了全读懂。是为了回答一个**"合上论文能讲给别人听"的问题**。

| 论文 | 核心问题 | 读完你应该能讲 |
|:----|:------|:------------|
| [Lilian Weng: LLM Powered Autonomous Agents](https://lilianweng.github.io/posts/2023-06-23-agent/) | Agent 由哪几块组成？ | "Agent = Planning + Tools + Memory + Action，每块解决什么" |
| [ReAct: Synergizing Reasoning and Acting](https://arxiv.org/abs/2210.03629) | 推理和行动怎么协同？ | "思考-行动-观察"的闭环是怎么走的？走了几步？ |
| [Reflexion: Language Agents with Reinforcement Learning](https://arxiv.org/abs/2303.11366) | Agent 怎么从失败中学习？ | "记忆 vs 反思 vs RLHF"——三种"让 Agent 变强"的路径区别 |

**读法**（肖璟"假设驱动"式读法）：
1. 先读 abstract + introduction → 写下"这篇论文声称解决了什么问题"
2. 看图 + 方法部分第一段 → 看和你想的是不是一样
3. 跳过数学 → 看实验结果 → "效果到底怎么样？比 baseline 好多少？在什么情况下失败？"
4. 合上论文 → 用两句话讲给别人听 → 讲不清楚 = 没读懂

### 0.2 画第一张结构图

读完三篇论文后，在白板上画——

```
AI Agent 的解剖图（我的第一版，粗糙不怕）

输入 = ?
  │
  ▼
[ ? ]  ← Agent 的"大脑"是什么？怎么决策？
  │
  ├→ 需要调用外部工具？→ [工具层] → 怎么调？怎么知道调哪个？
  │
  ├→ 需要记住之前的？→ [记忆层] → 短期怎么记？长期怎么存？
  │
  └→ 做完之后？→ [评估层] → 怎么知道做对了？错了怎么办？
  │
  ▼
输出 = ?
```

**画不出来 = 阶段零没完成。画出来但 MECE 不对 = 回去查漏。**

## 阶段一：逐层深入——MECE 拆解 + 假设验证（~4 周）

> 肖璟：将所有情况逐一拆解，构建所有可能情景，列出子假设。

### AI Agent 的 MECE 知识结构

```
                        AI Agent
                           │
        ┌──────────────────┼──────────────────┐
        │                  │                  │
    [感知层]           [认知层]           [行动层]
    怎么理解输入       怎么思考决策          怎么执行
        │                  │                  │
    ├─ 文本理解       ├─ 任务分解        ├─ 工具调用
    ├─ 多模态输入     ├─ 推理(LLM core)  ├─ 代码执行
    ├─ 上下文理解     ├─ 自我反思        ├─ API 编排
    └─ 意图/目标解析  ├─ 规划             └─ 多 Agent 协作
                     └─ 决策/选型
                          │
                    [记忆层] ←→ [评估层]
                    怎么存储         怎么判断对错
                          │                  │
                     ├─ 短期记忆       ├─ 自动评估(规则)
                     ├─ 长期记忆(RAG)  ├─ 自动评估(模型)
                     └─ 经验学习       └─ 人类介入

    → 每一列 = 一个"你要搞懂它内部发生了什么"的领域
    → 每一行 = 一个"这周要验证的子假设"
```

### 第 1 周：认知层——LLM 怎么"思考"？

**假设**：Agent 的认知质量 ≈ LLM 的推理能力 + Prompt 组织方式

**子假设和验证**：

| 子假设 | 验证方式 | 预期产出 |
|:------|:-------|:-------|
| H1: CoT 的本质是"让模型在生成答案前先把推理过程显式化" | 读 CoT 原论文 + 跑一个有/没有 CoT 的对比实验 | 理解 CoT 适用/不适用场景 |
| H2: ReAct 每一步的"Thought"是模型生成的，因此可以被错误推理"带跑" | 跑一个 ReAct demo + 观察"Thought"什么时候开始胡说 | 理解 Agent 失败的主要模式 |
| H3: 任务分解（Plan）的粒度是关键——太粗没用，太细太贵 | 读 Plan-and-Execute 论文 + 对比"先计划后执行"vs"边想边做" | 理解何时该 plan 何时该 react |

**周末产出**：一段 200 字的总结——"LLM 作为 Agent 大脑的三个核心能力和三个核心限制"。

### 第 2 周：行动层——Agent 怎么"动手"？

**假设**：行动的瓶颈不在"能不能调用工具"，在"调哪个工具、传什么参数、怎么处理返回结果"

**子假设和验证**：

| 子假设 | 验证方式 | 预期产出 |
|:------|:-------|:-------|
| H1: Function Calling 的可靠性取决于"工具描述"写得好不好 | 同一工具，写两种描述，看 Agent 选对的概率 | 理解 prompt engineering 对 Agent 的影响 |
| H2: 多步工具调用中最常见的失败是"上下文漂移"——中间结果把原始目标淹没了 | 跑 5 步以上的工具调用链 → 看任务完成率 | 理解为啥复杂任务 Agent 容易跑偏 |
| H3: 代码执行(Code Interpreter)比 API 调用更灵活但更不安全 | 读 CodeAct / SQL + Python Agent 论文 | 理解 Agent "行动"的不同选项及其 trade-off |

**周末产出**：500 字——"Agent 执行层的五个难点和当前解法"。

### 第 3 周：记忆层——Agent 怎么"积累经验"？

**假设**：记忆层是 Agent 目前最不成熟的层——短期靠窗口（有限），长期靠 RAG（粗糙）

**子假设和验证**：

| 子假设 | 验证方式 | 预期产出 |
|:------|:-------|:-------|
| H1: 短期记忆的核心矛盾是"窗口放不下" vs "塞太多会稀释注意力" | 读 Longformer / Block Recurrent Transformer 思路摘要 | 理解窗口限制的物理约束 |
| H2: RAG 解决的是"事实检索"，解决不了"经验积累和策略迭代" | 对比 RAG Agent vs 微调 Agent 的论文 | 理解 RAG 不能解决什么 |
| H3: Reflexion 让 Agent 用自己的失败经验形成"内部反思"——这是比 RAG 更高级的记忆形式 | 读 Reflexion 论文 + 跑 demo | 理解"从失败中学习"的 Agent 怎么设计 |

**周末产出**：一幅"Agent 记忆层的全景图"——短期/中期/长期各用什么方案、各自的局限。

### 第 4 周：多 Agent + 评估层——"团队"怎么协作？

**假设**：多 Agent 不是"多加几个 LLM 就行"——核心挑战是**避免冗余 + 保证一致性 + 通信效率**

**子假设和验证**：

| 子假设 | 验证方式 | 预期产出 |
|:------|:-------|:-------|
| H1: Multi-Agent 的核心价值不是"更聪明"，是"更可靠"（不同 Agent 互相 check） | 读 AutoGen / MetaGPT 论文 | 理解单 Agent vs 多 Agent 的 trade-off |
| H2: Agent 评估是学术界比工业界更头疼的问题 | 读 AgentBench / SWE-Bench 评估论文 | 理解"怎么知道 Agent 做得好不好"有多难 |
| H3: Human-in-the-loop 在可见的未来不可或缺 | 读 AutoGen 中 human feedback 的章节 | 理解为什么 Agent 目前不可能完全"自主" |

**周末产出**：一个"2025 年 AI Agent 真实现状"的一页纸总结——能做多好，做不了什么。

## 阶段二：动手贯穿始终

> 肖璟：光看报告不行，要持续应用才能内化。

### 每周必做

```
每周至少跑一个 Agent demo:
  W1: ReAct 最简单的 demo（调一个工具）
  W2: 加记忆（向量数据库 + 对话历史）
  W3: 加错误处理（工具调用失败怎么办？）
  W4: 多 Agent（两个 Agent 合作完成一个任务）
```

### 失败日志（最有价值的学习材料）

```markdown
* 时间：___
* 任务：___
* Agent 做了什么（出乎意料的事）：___
* 失败在哪一步：___
* 为什么失败——是因为：
    □ 模型幻觉？
    □ 工具描述写得不清楚？
    □ 窗口太长丢了目标？
    □ 规划粒度不对？
    □ 评估层没拦住错误？
* 如果让我改，我会怎么改：___
```

**一条失败日志 = 你对 Agent 内部机制的一次真正理解。**

## 阶段三：DIKW 自检——你的理解在哪一层？

> 肖璟的 DIKW 模型：数据→信息→知识→智慧。

每个周末用这个自检：

```
                    self-check
                       │
     ┌─────────────────┼─────────────────┐
     │                 │                 │
  停留在              能讲给别人听      能判断新论文
  读过了              为什么            真正的贡献在哪
     │                 │                 │
  数据/信息层          知识层             智慧层
  (还没学完)          (基本功)          (真正的认知)
```

**每周的目标是往前推一层：**
- W1-W2: 从"读了很多资料" → 能讲清楚"Agent 是什么"
- W3-W4: 从"能讲清楚" → 能判断"这篇论文真正贡献了什么"
- W5-W6: 从"能判断论文" → 能预判"下一步这个领域会往哪走"

---

## 验收标准：学习结束时你能回答这 5 个问题

**Q1**: 如果让你从零设计一个 Agent，你的架构图是什么？每层用哪些技术？为什么？
→ 答不出 = 阶段一没做完

**Q2**: 给你一篇新的 Agent 论文，你能辨别它真正的贡献在哪一层？是认知层的突破还是工程层的优化？
→ 答不清 = DIKW 没爬到知识层

**Q3**: 一个 Agent 任务失败了——你能定位是哪一层的 bug？是推理错了？工具调用错了？记忆丢了？评估没拦住？
→ 定位不了 = 阶段二失败日志不够

**Q4**: 初始假设对了几个？为什么对/错？
→ 这个对比 = 你真正学到的东西

**Q5**: 如果让你预测：2025 年底 Agent 能做到什么、做不到什么——你能给一个可证伪的预判吗？
→ 能 = 深度认知建立 | 不能 = 回去补阶段一

## 时间安排

```
阶段零（最小认知） : ~3-5 天    — 论文+结构图
阶段一（逐层深入） : ~4 周      — 每周深一层，周末产出
阶段二（动手验证） : 贯穿全程   — 每周一个 demo + 失败日志
阶段三（DIKW 自检） : 每周一次  — 周末 15min 自检
```

每天投入 1-1.5 小时，6 周后你建立的不是"关于 AI Agent 的谈资"，而是**真正的结构级认知**。
