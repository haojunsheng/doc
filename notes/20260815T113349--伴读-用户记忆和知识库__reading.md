# 逐段伴读记录

## 第一部分：用户记忆系统

### 第 1 节：记忆的本质（朋友模型比喻）

翻译与要点：记忆不是录音机，是筛子。选择性（不记临时信息）/ 抽象化（具体事件提炼为通用偏好）/ 结构化（便于检索）。

核心主张：记忆的目标不是"记录"，而是"形成一个关于用户的预测模型"。

碰撞记录：
- 读者判断：这应该是选择性记忆。
- Agent 微调：选择性回答"记什么"，但没回答"记成什么样"。人类朋友模型是模糊印象（"他大概率不吃香菜"），Agent 体系追求精确、可审查、可检索（"dietary restriction: vegetarian"）。"模糊模型 vs 精确数据库"的张力是本章暗线。

### 第 2 节：三层次评估框架

三层次（递进依赖，不是并列）：
1. **基础回忆**：精确返回用户直接提供的结构化信息（"会员号 12345"）。存取可靠性。
2. **多会话检索**：跨对象跨时间，检索所有相关信息并推理判断（两辆车时问"为我的车预约保养"→找出两辆并追问哪辆）。
3. **主动服务**：跨会话、预见性、从无关记忆中发现联系，无指令时主动规避问题（护照将过期→主动预警）。

碰撞记录：
- 读者判断：第二层和第三层的区别在于"是否需要人参与澄清"。
- Agent 精化：分界线不是"是否需要人参与"（第三层方案列表最终也要给人看），而是**谁发起了动作**——第二层是"任务内的澄清"（用户任务的延续），第三层是"任务外的发起"（系统自主启动）。

### 第 3 节：记忆层次结构与四种存储格式

层次结构（放哪里）：
- 轨迹 Trajectory：单次会话原始记录，append-only，只增不改 → 流水账
- 用户长期记忆：跨会话提炼的稳定信息，反复改写/合并/淘汰 → 档案
- 业务状态：任务逻辑阶段（"等待付款"），第四章展开

四种存储格式（怎么存）：
- Simple Notes：最小事实，O(1)，但关联全丢
- Enhanced Notes：完整上下文段落，语义完整，但冗余、难更新
- JSON Cards：三层嵌套结构，支持部分更新，但强制分类丢多维性
- Advanced JSON Cards：backstory/person/relationship/时间戳 → 情境化知识管理（消歧）

实践原则：关键且少量 → Advanced JSON Cards；大量且非关键 → Simple Notes；生产用混合模式。

### 第 4 节：User as Code（可执行记忆）

核心思想：前面四种格式本质都是文本——"存"和"用"是分开两步（先捞文本，再交给易出错的 LLM 去读去算）。User as Code 把介质换成可执行代码：带类型的 Python 对象保存用户状态，函数编码约束规则，"表示用户"和"推理用户"发生在同一个可被解释器运行的介质里。

两阶段：记忆阶段（事实逐条追加到只增不删的日志）+ 结构化阶段（周期性从日志重新生成带类型 Python，即"预写日志 + 周期性检查点"）。

三件从"LLM 心算"变"确定性代码"的事：聚合统计、冲突发现、约束执行。

碰撞记录：
- 读者判断：Python 比较通用，工具链绑定不是问题。
- Agent 微调：Python 通用这点成立。但真正的代价有二：(1) 可读性——代码记忆的读者是解释器，文本记忆的读者可以是用户自己（后文 OpenViking 强调 Markdown 可读可编辑可修正）；(2) 类型化要求提前知道结构，而记忆是演化的，无法类型化的只能堆进 `notes: list[str]` 兜底。

### 第 5 节：认知科学三分类（存什么）

- 情景记忆 Episodic：具体事件（上周三那顿晚餐 / 具体订票记录）
- 语义记忆 Semantic：一般知识（首都是罗马 / 用户是素食者）
- 程序记忆 Procedural：行为流程（骑自行车 / 订机票通用流程）

三套分类体系正交，可自由组合：语义记忆 + Simple Notes + 长期记忆；程序记忆 + Advanced JSON Cards。

### 第 6 节：框架案例——Mem0 与 Memobase

**Mem0**：
- 2025 v2：写入时消歧（LLM 决定 ADD/UPDATE/DELETE/NOOP）。记忆库简洁，但错误更新不可逆丢历史。
- 2026 v3：仅追加写入（只 ADD，冲突并存）+ 检索时排序（语义+BM25+实体+时间）。LoCoMo 71.4→92.5。

**Memobase**：用户画像（Profile，可配置槽位）+ 事件记忆（Event Memory，时间线）；缓冲批处理摊薄成本。

碰撞记录：
- 核心问题：选择（v2）vs 全保留再排序（v3），什么决定该选哪边？
- 读者判断：同意"错误代价决定"的判断。
- Agent 压力测试与回应：存在"风险不对称"——错排可重试，错删不可逆（append-only 的精髓：宁可多留，不可错删）。但全保留有账单（记忆爆炸、检索变慢、冲突打架）。
- 第三级答案：**版本化冲突检测 / 场景限定（qualification）**——不删但分层，用时间戳+场景标出冲突事实各自的适用条件。（后文"定期整理"正式登场）

### 第 7 节：压缩整理与隐私保护（流读）

- 重要性评分：访问频率 + 时间衰减 + 情感强度 + 信息独特性
- 聚类生成代表性摘要（二级存储归档）
- 抽象泛化：情景 → 语义/程序记忆
- 隐私保护：本地小模型（Qwen3 0.6B）PII 脱敏，LLM 召回 95%+，混合策略正则+LLM

## 旁逸记录

### 双编码器/跨编码器的两级漏斗

混合检索"双编码器先粗筛、跨编码器再精排"，与人类做高成本决策是同一个形状：先靠廉价信号大规模淘汰，再对幸存者投入昂贵注意力（医生分诊、HR 筛简历、相亲划卡片）。原因：昂贵资源单位成本高，用便宜资源先把空间砍小。RAG 用算力重新发明了这个古老结构。

## 第二部分：RAG 基础（伴读记录）

### 文档分块（展开）

- 为什么分块：嵌入长度限制 / 窗口经济 / 一个向量只能精确表达一个主题（本质）
- 三种策略：固定大小（无视结构）→ 结构感知（尊重显式结构）→ 语义切分（尊重隐式语义）
- 块大小权衡：无绝对值，取决于查询类型（找事实→小块，理解论证→大块）
- 重叠：承认"切错"不可避免，留冗余
- 固有缺陷：切断上下文（"该公司"指代丢失）→ 后文上下文感知检索的伏笔
- 碰撞：检索是否与知识连续性根本冲突 → 修正为"贫瘠的查询撞上连续的知识"

### 稠密嵌入（展开）

- 哲学根基：分布假设（Firth「观其伴，而知其义」），共现=语义的代理
- 关键结论：向量捕捉"可替换性"而非"意义"（反义词向量也近）
- 语义几何化：国王-男性+女性≈女王（是统计副产品，不是"理解"）
- Word2Vec→BERT：静态（词典）→ 动态（语境的函数），bank 困境 = 多主题稀释
- 碰撞：检索要"相关"还是"相同"？读者判断"相关更重要"

### 稀疏嵌入（展开）

- 哲学根基：词袋模型，主动放弃词序 → 换可索引性（倒排索引）
- TF-IDF：TF（文档内）+ IDF（跨文档区分度，信息论味）
- BM25：词频饱和 + 长度归一化（重要性边际递减）
- 稠密 vs 稀疏：统计 vs 学习 / 可解释 vs 黑箱 / 字面 vs 语义
- 碰撞：稀疏稠密是"相关"的两个互补通道（字面相关 vs 语义相关）

### 混合检索（展开）

- 难点：两路得分不可比（苹果橘子）
- 三阶段：并行检索 → 结果融合(RRF) → 神经重排序（先便宜后昂贵漏斗）
- RRF：抛得分看排名，k=60 平滑；母题"简单鲁棒 vs 复杂脆弱"
- 双编码器（独立）vs 跨编码器（交互）
- 碰撞：上游粗放下游兜底的前提是"下游比上游强"；系统性错误会让兜底失效

## 第三部分：超越扁平文本（伴读记录）

### 结构化索引：RAPTOR / GraphRAG

- RAPTOR（树状层次摘要）vs GraphRAG（实体关系图，多跳推理+实体消歧）
- GraphRAG 局限：语义降级（条件逻辑、时间依赖压成三元组后丢失）→ 分层互补

### OpenViking 文件系统范式

- L0/L1/L2 按需加载（与 Skills 渐进式披露同源）
- Markdown 纯文本决策：读者是"用户自己"（可读可审可回滚）
- 链接索引：用文件链接维持知识连续性，回应"检索 vs 连续性"的张力

### 知识更新

- 增量更新：Proposer-Reviewer 四步 PR 闭环
- 异源互审（降坑）+ 回到原始证据（填坑）
- 母题：LLM 判断需要"压舱石"——模型之外的锚点（解释器/原始记录/原始上下文/原始证据）

### 问题驱动串联（降维复盘）

- 读者反馈"整体复杂看不懂" → 用「问题→方案→缺陷→新方案」思路重串整章
- 核心节奏：每个新技术出场，前面一定站着一个没修好的坑

### 两条支线的根本差异（读者暂存待想）

- 作者官方说法：同一问题，尺度不同（个体 vs 群体）
- 挖出的：用户记忆 = 推断出来的知识（侦探），知识库 = 既存的知识（图书管理员）
- 底层同（存和找）、上层异（推断 vs 组织）
- 汇合的解释：记忆放大成"个人知识库"，知识细化成"结构化记忆"

## 终局问题

**（读者暂存，待再想）** 用户记忆与知识库，为什么会被拆成两条支线？它们的根本差异究竟是"解决的问题不同"还是"解决方案不同"？

- 初步挖到的一层：用户记忆是**推断出来的知识**（从对话噪声里猜，模糊、易错、演化中），知识库是**既存的知识**（有人写好的、权威、稳定）。
- 由此推出：底层问题相同（存和找），上层挑战不同——用户记忆的核心是"推断"（消歧/冲突/遗忘），知识库的核心是"组织"（索引/检索）。
- 尚未想通的部分：这个"推断 vs 组织"的差异，还意味着什么？它如何决定了两条线各自的全部设计取舍？
